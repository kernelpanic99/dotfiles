# General

- no em-dashes

# Code style

- no naked block statements: even single line block statements should have braces
- vertical spacing: separate different kind of statements and blocks with empty lines
- comments: do not comment unecessarily if the context is obvious from the code.

# Documentation style

- Documents describe the final approach only. State what IS, in the affirmative.
- Never include contrastive/corrective framing ("as opposed to...", "instead of...",
  "rather than the earlier...", "note that we are NOT...").
- Corrections I make in chat are context for you, not content for the doc. Do not
  memorialize the decision path or rejected alternatives unless I explicitly ask for
  a "rationale" or "alternatives considered" section.
